아래로 갈수록 위의 것을 씁니다. 위에서부터 읽으면 앞으로 되돌아갈 일이 없습니다.

**읽는 요령**: 모든 파일 맨 위 docstring에 "이게 뭔지"와 "왜 이렇게 생겼는지"가 있습니다. 함수 안 주석은 **왜**만 적었습니다 — 무엇을 하는지는 코드가 말합니다.

### 왜 `slots.py`와 `scorer.py`가 따로 있나

**계산과 AI를 파일로 가릅니다.** `slots.py`·`scorer.py`가 숫자를 정하고, 나중에 올 `agent_loop.py`가 그 숫자를 말로 설명합니다.

섞으면 "이 점수 누가 정했냐"가 흐려지고, 리허설과 본 시연이 같은 답을 낸다는 보장이 무너집니다. LLM은 매번 다른 말을 하지만 점수는 매번 같아야 합니다.

## 3. 요청 하나가 흐르는 길

조율 시작(`POST /rooms/1/schedulings`)이 가장 깁니다. 이걸 따라가면 나머지는 다 비슷합니다.

```
main.py           쿠키를 열어 세션 딕셔너리로 만든다 (SessionMiddleware)
  ↓
auth.py           current_user_id — 쿠키에서 user_id. 없으면 401
  ↓
meeting/router.py start()
                    room이 있나?                없으면 404
                    room.leader_user_id == 나?  아니면 403 (팀장만)
                    시각에 오프셋이 있나?        없으면 400
                    기간이 거꾸로인가?           그러면 400
  ↓
meeting/service.py start_scheduling()      ← db-설계.md §6의 1~3번
   1  scheduling 한 행 (status='running')
   2  팀원 ids → preference → 시간표 → 확정된 회의
      slots.expand_busy()      주간 수업을 기간 안의 실제 구간들로 펼침
      slots.find_candidates()  30분 격자 × 전원 가능 시간 안 × 팀 회의와 안 겹침
   3  scorer.score_slot()      사람마다 1~5점 + 이유 한 줄
      두 명 이상 못 오는 후보는 버림 (1명 불참안만 있으므로)
      scorer.pick_order()      전원 가능 먼저 → 양보 가중 낮은 순 → 이른 시각
      상위 5개를 candidate_slot + slot_cost로 저장
  ↓
meeting/router.py _to_out()    후보 개수와 발언만 담는다
                               ** 점수와 total_cost는 담지 않는다 **
```

**후보가 아예 없으면 `status`가 `failed`입니다.** 후보는 있는데 **전원 가능한 것이 하나도 없으면** 라운드를 한 번도 안 돌고 판단 에이전트가 바로 정해 `settled`가 됩니다(11/5). 그때도 후보는 저장됩니다(`absentee_user_id`가 찬 상태로).

서버가 몰래 기간을 넓히지 않습니다 — 넓히는 건 팀장이 더 넓은 기간으로 조율을 새로 여는 선택이고, 몰래 하면 "왜 이 시간이죠"에 답할 수 없습니다.

## 4. 제가 정한 것과 이유

문서에 안 적혀 있어서 제가 골랐습니다. **바꾸고 싶으면 다 바꿔도 됩니다** — 바꿀 때 어디가 같이 움직이는지만 적어 뒀습니다.

| 정한 것 | 왜 | 바꾸면 같이 움직이는 곳 |
|---|---|---|
| **로그인은 이름만.** 비밀번호 없음 | `user`에 비밀번호 열이 없고 그 테이블은 레인 B 것입니다. `/me/*`가 사용자 없이는 아예 안 돌아서 먼저 깔았습니다 | `shared/auth.py`의 `login()` 안. 검사 한 줄이 들어갈 자리를 주석으로 적어 뒀습니다 |
| **쿠키를 서명** (`SessionMiddleware`) | 서명 안 하면 쿠키 값이 그냥 `1`이라 누구나 다른 사람이 됩니다. `db-설계.md`가 이미 "서명 쿠키" 로 정해 뒀습니다 | `.env`의 `SESSION_SECRET` |
| **데모 헤더를 안 넣음** | 한 창에 폰 화면 2개를 띄울지가 미정입니다. 정하면 `current_user_id`에 세 줄을 더합니다 | `db-설계.md` §9-1 |
| **질문 1을 피커로** (숫자+오전·오후, 30분) | 자유 입력을 받으면 한국어 시각 파서가 필요하고, 그건 LLM이거나 깨지는 정규식입니다 | 디자인 브리프의 온보딩 질문 1. 명세에 반영 필요 |
| **`interpret`가 저장까지** | 온보딩 화면에 확인 단계가 없고 버튼이 하나입니다. 나누면 두 번째 호출이 실패할 때 반쯤 저장된 상태가 남습니다 | 명세의 `interpret` 비고 |
| **`avoid_polished`를 비워 둠** | LLM 공급자를 안 골랐습니다. 원문을 복사하면 조율이 사람 말을 그대로 읊는데, 브리프가 금지한 것입니다 | LLM이 붙을 때 채웁니다 |
| **가능 시간은 하드 제약** | 질문이 "몇 시부터 몇 시까지 **가능**해요?"입니다. 선호가 아니라 가능 여부입니다. 전원 교집합이 비면 후보가 없어 `failed` | `slots.within_day_range()` |
| **한 사람만 안 되는 후보는 남김. 두 명 이상은 버림** | 한 명이 빠지는 건 1명 불참안의 재료입니다. 두 명이 빠지는 회의는 브리프에 없어서 저장하면 라운드가 쓸 수 없는 행만 쌓입니다 | `slots.find_candidates()` · `service.py` |
| **오프셋 없는 시각은 거절** | 받아 주면 조용히 틀립니다. naive에 `astimezone(KST)`를 부르면 **서버의 시간대**로 해석하므로, 배포 서버가 UTC면 오전 9시가 오후 6시가 됩니다 | `meeting/router.py._require_offset()` · `demo_clock.set_clock()` |
| **조사(와/과)를 받침에 맞춰 붙임** | 에이전트가 이 문장을 그대로 말합니다. "알바과 겹칩니다"는 바로 보입니다 | `scorer.with_particle()` |
| **시간대 경계** (아침 6–9, 오전 9–12, 점심 12–14, 오후 14–18, 저녁 18–21, 밤 21–24) | 브리프가 이름만 정하고 몇 시부터인지는 안 적었습니다 | `scorer.DAYPART_RANGES`. 화면 설명도 같은 값을 써야 합니다 |
| **붙어 있으면 +2 → 3점("조금")** | 브리프 예시 "수업 바로 뒤라 조금 빠듯하지만 괜찮아요"가 그 자리입니다. 30분 이상 떨어지면 벌점 없음 | `scorer.TIGHT_GAP`·`TIGHT_PENALTY` |
| **양보 가중은 순서만 바꿈** | 저장되는 `score`는 사람이 실제로 느끼는 값이어야 시연에서 열어 보여 줄 수 있습니다. 누적 양보 0 → ×1.0, 4 이상 → ×2.0 | `scorer.YIELD_WEIGHT_STEP` |
| **후보는 라운드당 5개만 저장** | 한 주 기간에서 채점기가 수십 개를 만듭니다. 전부 저장하면 `round_no`("몇 번째 라운드가 고려했나")의 뜻이 흐려집니다 | `service.CANDIDATES_PER_ROUND` |
| **에러 모양을 `{code, field, message}`로** | FastAPI 기본값은 `{"detail": ...}`에 검사 실패는 422입니다. 그대로 두면 프론트가 엔드포인트 수만큼 문구 표를 만듭니다 | `main.py`의 예외 처리기 둘 |
| **`service.py`를 조율에만 둠** | 온보딩은 "변환하고 저장" 한 줄씩이라 층을 더하면 읽을 게 늘기만 합니다. 조율은 순서가 8단계라 필요합니다 | — |

## 5. 다음에 할 것 — 순서대로

### ① LLM 공급자 고르기 `[막고 있음]`

**이게 없으면 시연의 핵심 화면이 안 됩니다.** 무료로 카드 없이 되는 건 Gemini AI Studio와 Groq입니다. 한도는 수시로 바뀌니 콘솔에서 직접 봐야 합니다.

고르고 나서 `app/shared/llm.py`를 **OpenAI 호환 Chat Completions**로 짜면 공급자를 환경변수로 바꿀 수 있습니다.

```
LLM_ENABLED=true
LLM_BASE_URL=...
LLM_MODEL=...
LLM_API_KEY=...
```

함수 하나면 됩니다 — `complete_json(prompt) -> dict | None`. `None`을 주게 만드는 게 핵심입니다. 키가 없거나 공급자가 죽어도 앱이 끝까지 돌아야 합니다.

### ② 라운드 돌리기 (`agent_loop.py` · `prompts.py`)

`db-설계.md` §6의 4~5번입니다. 후보와 점수는 **이미 DB에 있습니다** — 읽어서 말로 설명하는 것부터 하면 됩니다.

- `candidate_slot`에서 `proposed=true`로 바꾸며 제안
- 판단 에이전트 + 팀원 에이전트 발언을 `utterance`에 `seq` 순으로 쌓기
- 거절이 나오면 `membership.yield_total`을 보고 다음 후보 (`scorer.pick_order`가 이미 해 줍니다)
- 합의 → `scheduling.status='agreed'` + `meeting`(`proposed`) + 팀원 수만큼 `meeting_response`(`pending`)

### ③ SSE (`GET .../schedulings/{id}/stream`)

1.6초마다 발언 하나. **스피너 금지** — 이 10~20초는 로딩이 아니라 구경거리입니다.

**라운드는 여기서 안 돕니다.** 조율 시작(`POST /schedulings`)이 뒷단 스레드를 띄우고(`meeting/runner.py`), 스트림은 쌓이는 발언을 따라 읽기만 합니다. 전에는 이 응답 안에서 돌렸는데 그러면 조율 전체가 **보는 사람 한 명의 연결**에 묶입니다 — 두 번째로 연 사람은 그때까지 쌓인 것만 보고 끝났고, 탭을 닫으면 조율이 거기서 멈춰 그 방이 영영 새 조율을 못 열었습니다.

읽기만 하므로 갈래가 하나입니다. 늦게 열어도 처음부터 같은 속도로 보고, 아직 도는 중이면 새 발언이 나오는 대로 이어 봅니다. 몇 명이 같이 열어도 서로 아무 영향이 없습니다.

### ④ 회의와 수락·거절

여기에 **가장 조심할 것**이 있습니다.

> 전원 수락 시 자동 확정이라 확정 버튼이 없습니다. **마지막으로 수락한 사람의 그 요청이 유일한 기회**입니다. 맨 앞에서 `meeting`을 `SELECT ... FOR UPDATE`로 잠그지 않으면, 두 사람이 동시에 수락할 때 아무도 확정되지 않거나 `yield_entry`가 두 번 들어갑니다.

시연이 한 창에 폰 화면 2개라 **진짜로 동시에 눌립니다.**

### ⑤ 나머지

홈, 알림 4개, 일정, 내 프로필, 주간 시간표, 일정 직접 추가.

`POST /me/schedule/items`(일정 직접 추가)는 **온보딩 다음 화면**인 "일정 연결"의 직접 입력 길입니다. 시드에 시간표가 이미 있어서 조율 테스트는 되지만, 화면을 만들려면 필요합니다.

### 코드를 쓸 때 지킬 것 셋 (README에도 있습니다)

1. **`datetime.now()`와 SQL `NOW()`를 쓰지 않습니다.** 판정의 "지금"은 `shared.demo_clock.now(session)`입니다
2. **naive `datetime`을 만들지 않습니다.** 전부 `+09:00`이 붙은 aware입니다
3. **입력 검사를 모델 클래스에 기대지 않습니다.** SQLModel은 `table=True`에서 Pydantic 검사를 끕니다 — 그래서 `schemas.py`(검사)와 DB `CHECK`(진짜 방어선)가 둘 다 있습니다
