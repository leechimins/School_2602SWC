# 에브리타임 시간표 가져오기 — 계획

**11월 5일.** 아직 만들지 않았습니다. 무엇이 되고 무엇이 안 되는지 확인한 것만 적어 둡니다.

조율이 쓸 수 있는 시간표가 지금은 `tools/seed.py`에 박힌 것뿐입니다. 사람이 자기 시간표를 넣을 길이 없어서, 시연에서 "제 시간표 넣어 볼게요"가 안 됩니다. 이 문서가 그 구멍을 어떻게 메울지입니다.

---

## 1. 확인한 것 — 서버는 에브리타임을 못 읽습니다

직접 요청해 봤습니다.

```
GET  everytime.kr/robots.txt          →  User-agent: *
                                          Disallow: /
POST api.everytime.kr/find/timetable/table/friend  →  HTTP 403
GET  everytime.kr/@<공유ID>                         →  HTTP 403
```

**기술적으로 막혀 있고(403) 정책적으로도 막혀 있습니다(`Disallow: /`).** 우회하지 않습니다 — 약관 위반이고 차단 대상입니다.

그래서 **명세의 `POST /me/integrations/everytime`은 지금 설계로는 만들 수 없습니다.** 비고에 적힌 "링크 붙여넣기"는 서버가 그 링크를 읽을 수 있다는 전제인데, 그 전제가 틀렸습니다.

참고한 프로젝트([seongbin45/airports-near-me#10](https://github.com/seongbin45/airports-near-me/pull/10))도 같은 결론에 도달해 있었습니다 — *"서버는 에브리타임에 접속하지 않는다(403·robots Disallow)."*

### 다른 프로젝트가 된다고 하는 이유

`sookcha/every2cal`은 로그인 없이 공유 ID로 읽는다고 적어 뒀습니다. 그건 **사용자 자기 PC에서 돌리는 CLI**입니다. 요청이 개인 IP에서 한 번 나가는 것과 서버에서 반복해 나가는 것은 상황이 다릅니다.

---

## 2. 그래서 가능한 길 — 브라우저가 읽고 서버는 받기만

```
사용자 브라우저                              우리 서버
─────────────                              ─────────
에브리타임 공유 페이지를 연다
      ↓
페이지가 스스로 부르는 XML을
북마클릿이 복사한다
      ↓
우리 화면에 붙여넣는다
      ↓
브라우저에서 파싱 → 미리보기 ──────────→  POST /me/schedule/items
                                            (파싱된 시간표를 받아 저장)
```

**서버는 에브리타임에 한 번도 접속하지 않습니다.** 사람이 자기 브라우저로 자기 시간표를 본 결과를 보내는 것뿐입니다.

### 그래서 필요한 엔드포인트는 하나입니다

| | |
|---|---|
| ~~`POST /me/integrations/everytime`~~ | **안 만듭니다.** 서버가 링크를 못 읽습니다 |
| **`POST /me/schedule/items`** | 파싱된 시간표를 **여러 칸 한 번에** 받습니다 |
| `DELETE /me/schedule/items/{id}` | 한 칸 지우기 |
| `DELETE /me/schedule/groups/{id}` | 묶음 통째로 지우기 (다시 불러올 때) |

직접 입력도 같은 엔드포인트를 씁니다. 받는 모양이 같으니 두 번 만들 이유가 없습니다.

---

## 3. 아직 모르는 것 — 이것부터 확인해야 합니다

**실제 공유 링크 하나가 필요합니다.** 본인 에브리타임에서 시간표 공유를 켜면 `everytime.kr/@XXXXXX` 같은 주소가 나옵니다. 그걸로 확인할 것:

- [ ] 그 페이지를 **브라우저에서** 로그인 없이 열 수 있나
- [ ] 페이지가 부르는 XML의 모양 (`api.everytime.kr/find/timetable/table/friend`)
- [ ] XML의 요일 번호가 0=월인가 1=월인가
- [ ] 시각이 분 단위인가 5분 단위인가 교시인가
- [ ] 학기 범위(`valid_from`·`valid_to`)를 거기서 알 수 있나
- [ ] 비공개 시간표면 어떤 응답이 오나

**이걸 모르면 `POST /me/schedule/items`의 모양을 못 정합니다.** 지금 만들면 파싱 결과를 보고 다시 고치게 됩니다. 그래서 지금 안 만듭니다.

## 4. 만들 때의 모양 (초안)

`schedule_item` 테이블은 이미 이걸 받을 수 있습니다. 새 칸이 필요 없습니다.

```json
POST /me/schedule/items
{
  "source": "everytime",
  "replace_group": null,
  "items": [
    { "kind": "class", "title": "서비스디자인",
      "recurrence": "weekly", "weekdays": [1], 
      "start_min": 780, "end_min": 870,
      "valid_from": "2026-09-01", "valid_to": "2026-12-20" }
  ]
}
```

- **여러 칸을 한 번에** 받습니다. 수업 10개를 10번 부르면 중간에 실패했을 때 반쯤 들어간 시간표가 남습니다
- `weekdays`가 배열인 이유는 명세의 "요일 여러 개를 한 번에"입니다. 월·수 같은 수업 하나가 행 둘이 되고 `group_id`로 묶입니다
- `source`가 `everytime`이면 다시 불러올 때 **그 출처의 기존 칸을 지우고 새로 넣습니다.** 손으로 넣은 것(`manual`)은 안 건드립니다
- `kind`가 `appointment`면 `title`을 서버가 비웁니다 — 개인 약속 제목을 팀원에게 보여 주지 않습니다(이미 모델 주석에 있는 규칙)

## 5. 구글 캘린더는 빼는 쪽입니다

OAuth라 피할 수 없는 것이 있습니다 — GCP 프로젝트, 동의 화면, client id/secret, 리다이렉트 URI, 토큰 저장과 갱신, 동기화 엔드포인트. 검증은 "테스트" 상태로 두면 안 받아도 되지만(테스트 사용자 100명까지) 심사위원 계정을 미리 등록해야 합니다.

명세에도 **Low**이고 "팀 전체 빼는 2순위"로 적혀 있습니다. 13일 남은 일정에서는 **직접 입력 + 에브리타임**까지가 현실적입니다.

## 6. 명세에 고칠 것

이 계획대로 간다면 명세의 아래 줄들이 바뀝니다. **아직 안 고쳤습니다** — 실제 XML을 보고 모양이 정해진 뒤에 한 번에 고치는 게 맞습니다.

| 줄 | 어떻게 |
|---|---|
| `POST /me/integrations/everytime` | 빗금. 서버가 링크를 못 읽습니다 |
| `DELETE /me/integrations/everytime` | 빗금. 위와 같음 |
| `POST /me/schedule/items` | 비고에 "여러 칸 한 번에, 에브리타임 파싱 결과도 이 길로" |
| 구글 캘린더 3줄 | 비고에 "13일 일정에서는 안 만드는 쪽" |
